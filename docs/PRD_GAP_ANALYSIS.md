# PRD v1.1 gap analysis — Robert and Natalie wedding website

**Audit date:** 2026-09-21.
**Scope:** every numbered requirement (IA, DES, TPL, HOME, CONTENT, RSVP, ADMIN, DATA, ARCH, SEC, NFR, AT, RELEASE, OPS) and every un-numbered requirement (document control, basis table, routes, journeys, content master, form sequence, data entities, configuration keys, success measures, decision table, handover package, sources register) in `docs/PRD_v1_1.md`.
**Repository state audited:** the repository after commit `68e4844` "Add PRD v1.1 to the repository as the governing specification", read at HEAD `7f8d326` on 2026-09-21 together with the working tree at that time (which additionally held `docs/selection/proofs/alt-b-couple-template/` as untracked). Line numbers cited below refer to that state; several findings were first raised against an earlier tree and corrected by the verifiers (see "Verifier overrides").
**Method:** an auditor classified each requirement from repository evidence; independent verifiers re-checked every finding against the files, `npm run build` output, `git status` and `git ls-files`, and overrode the auditor where the evidence had moved.

## Summary

253 requirements were assessed. 48 are **met** with evidence in the repository, 128 are **partial**, 20 are **missing**, 36 are **backend-required** (they cannot be satisfied by a static GitHub Pages site and depend on the server-side RSVP/admin service), and 21 are **owner-input-required** (blocked on a decision or content from Robert, Natalie or the coordinator). No requirement was classified not-applicable; the items the PRD itself defers (P2 features, procurement when nothing is purchased) are listed in section 7 for completeness. The static guest site is substantially complete: the invitation, wedding-day cards, Travel & Stay, FAQs, privacy notice, calendar files, the owner-directed envelope landing (sealed envelope, opened invitation, docked lower-left keepsake that re-centres in a dialog), reduced-motion and keyboard paths, and the accessibility/performance evidence in `docs/evidence/` are in place. The largest open areas are (1) the Section 05 selection package and the G1/G2/G3 approvals, which the owner's "start building the website" direction bypassed and which have not been formally waived or signed; (2) the RSVP/admin service, which exists as a tested Cloudflare Workers + D1 reference implementation under `backend/` but is not deployed, so `rsvp.mode` remains `coming-soon`; (3) owner and coordinator inputs (RSVP cutoff, private contact route, venue entrances/parking, room block, visibility decision, typeface approval, retention approval) that are launch blockers in the build report; and (4) a set of documents that other repository files cite but that do not exist (`docs/selection/SELECTION_REPORT.md`, `CANDIDATE_REGISTER.md`, `SCORECARD.md`, `KEEP_ADAPT_REPLACE.md`), which must be produced or the references corrected.
